# Chip view of the partition (Phase 3b)

`specifications/hardware_config.json` v1.0 is generated by `run_hardware_config.py` from `chip_profile.json`.
The previous file is kept as `hardware_config.compiler_v2.json`.

## Two views of every plan
| View | Geometry | Purpose |
|---|---|---|
| compiler (`plan.totals`, `x2_tiles`) | 64-row PE, `hw["compiler_v2"]` (BMsemi `core/mapping.py` PEGeometry default, the "YOLO26 / FP4LLM" PE) | proves the compiler artifact is read correctly: still must equal `compiler_expected_tiles` (24 for tiny MobileNetV2) |

| Field | Value | Source |
|---|---|---|
| `x2.rows/cols` | 32 x 32 | `RERAM_CIM_32x32.v` ROW_INDEX0-4 / COL_INDEX0-4; `cim32x32.sv` l.484 `array_state [0:31]` |
| `x2.blocks` | 2 | `.FABulous/bel.txt` l.899 (X20Y6), l.2068 (X20Y14) |
| `x2.cell_bits` | **4 (decision, 2026-11-13)** | follows BMsemi `deep_gate/Crossbar_array.py` l.127, 165 (4-bit banks). The chip repo's model computes with 1 bit (`cim32x32.sv` l.802, 847-848); `run_hardware_config.py --cell-bits 1` models that |
| `x2.timing_cycles` | read 160, program 360, compute 450 | `cim32x32.sv` l.14-16 (behavioral model, not silicon) |
| `weights` | signed INT8, 2 sign banks x 2 four-bit banks = 4 cells (16 with 1-bit cells) | BMsemi `deep_gate/Crossbar_array.py` l.29-30, 127, 165 |
| `efpga` | 2160 LC, 18 MACC, 36 RAM32x4, 4 GBUF, 36 pins | `bel.txt` BEL counts; team: all[0..27] are example pins |

Open question for the team: is the silicon cell 4-bit (as configured, following DeepGate) or 1-bit (as the chip's
behavioral model computes)? 4-bit plans cannot be checked in the chip's behavioral simulation, which is binary.
The tests run every chip check with both cell sizes.

## How layers map onto the X2
* taps `(C/groups)*R*S` -> rows; outputs x 16 cells -> columns (bit planes and sign banks are separate columns,
  combined afterwards by shift-and-add).
* Grouped and depthwise convs: each group has its own inputs, so groups share a tile only on separate rows AND
  separate columns (block-diagonal; unused cells stay RESET = 0).
* The planner writes the exact placement (`plan.chip.layers.<layer>.placement`). `validate_partition` checks any
  placement independently (inside 32 x 32, no shared rows or columns within a tile, every weight cell exactly once)
  and recomputes every chip total from it.

## Schedule and cost
* More tiles than blocks: layers are either **resident** (programmed once) or **streamed** (reprogrammed every
  inference). If anything is streamed, one block must stay free to stream into, so 1 block can be resident.
* The baseline picks the resident set that saves the most programming (`chip_x2.best_resident_set`). A1 does not
  choose it yet: that would change the "exactly one legal plan" behaviour and is the next step.
* Cycles: compute = per MVM 32 beats + COMPUTE_DELAY + 32 results (lower bound); programming = every weight cell
  SET once at PROGRAM_DELAY (upper bound; the true count depends on weight values).
